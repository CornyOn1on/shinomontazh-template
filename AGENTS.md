# AGENTS.md — правила работы над проектом

Инструкция для любого ИИ-агента и разработчика, который открывает этот проект.
Читай перед первым изменением кода.

---

## 0. Сначала — контекст

Прочитай в таком порядке:

1. `PROJECT_BRIEF.md` — что это за проект и каковы границы.
2. `skills/tire-service-site/SKILL.md` — правила работы и чек-лист.
3. `README.md` — как запускать, собирать и передавать клиенту.
4. `.pages.yml` — какие данные доступны владельцу через панель.

Только после этого переходи к коду.

---

## 1. Изучи существующие файлы, прежде чем что-то менять

- Прочитай файл целиком или нужный фрагмент перед правкой.
- Проверь, нет ли уже готовой реализации нужного поведения.
- Смотри на соседние компоненты и придерживайся их стиля.

---

## 2. Не удаляй пользовательские изменения

- Незнакомый код, незакоммиченные правки, новые файлы — это чья-то работа.
- Не перезаписывай и не удаляй их без явного указания.
- Сомневаешься — спроси, а не «убирай за собой».

---

## 3. Не меняй архитектуру без необходимости

- Стек зафиксирован: React + TypeScript + Vite + CSS + GitHub Pages + Pages CMS.
- Новую библиотеку добавляй только если без неё задача не решается.
- Не переписывай рабочее решение ради «более красивой структуры».

---

## 4. Проверяй сборку после изменений

Всегда, перед тем как считать работу законченной:

```bash
npm run typecheck
npm run build
```

Обе команды должны проходить без ошибок. Если сломалось — чини до конца.
Не оставляй ошибки TypeScript и незаполненные TODO.

---

## 5. Используй реальные фотографии из проекта

- Сначала проверь `public/images/company/` — там могут быть реальные фото.
- Если фотографии есть — используй именно их.
- Не заменяй реальные фотографии заглушками.

---

## 6. Заглушки — только при отсутствии реальных фотографий

- Заглушки лежат в `public/images/placeholders/` и помечены `isPlaceholder: true`.
- Не подключай случайные внешние ссылки на картинки и не используй
  изображения, которые могут внезапно исчезнуть.
- Если добавляешь заглушку — укажи это в данных и в README.

---

## 7. Не хардкодь данные компании внутри компонентов

Плохо:

```tsx
<h1>Шиномонтаж в Щёкино</h1>
<a href="tel:+70000000000">Позвонить</a>
```

Хорошо:

```tsx
<h1>{site.heroTitle}</h1>
<a href={buildTelUrl(site.phone)}>Позвонить</a>
```

Всё, что владелец может изменить, обязано жить в `content/` и попадать
в компоненты через `src/data/content.ts`. Новые поля добавляй сразу в
`src/types/content.ts`, `content/*.json` и `.pages.yml`.

---

## 8. Проверяй мобильную версию

- Нет горизонтальной прокрутки на 360, 414, 768, 1024, 1280 и 1920 px.
- Крупные поля формы, удобные карточки, кликабельные телефон и мессенджеры.
- Фиксированная нижняя панель на мобильных не перекрывает контент.

---

## 9. Не добавляй секреты в клиентский код

- Никаких токенов, ключей, паролей и PAT — ни в компонентах, ни в `public/`.
- Репозиторий должен быть безопасно публикуемым.
- Персональные данные клиентов в репозиторий не попадают.

---

## 10. Не добавляй Telegram-бота

- Telegram Bot API запрещён.
- Автоматически отправить сообщение в чужой личный чат из статики невозможно.
- Сайт только готовит текст и открывает чат. Отправляет пользователь.

---

## 11. Не используй Supabase

Ни Supabase, ни другие базы данных, ни серверный backend.
Сайт должен оставаться полностью статическим после сборки.

---

## 12. Не считай заявку отправленной до действия пользователя

- Сообщение «Заявка отправлена» показывать запрещено.
- Пока пользователь не нажал кнопку отправки в мессенджере, заявка
  считается неотправленной.
- Формулировки: «Telegram открыт с готовым текстом заявки…»,
  «Текст заявки скопирован…».

---

## 13. Не выдавай `/admin/` за полноценную CMS

- `public/admin/index.html` — честная инструкция для владельца.
- Никакой имитации сохранения данных, никаких токенов в браузере.
- Кнопка ведёт на `https://app.pagescms.org/`.

---

## 14. Проверяй, что владелец имеет доступ только к своему репозиторию

- Pages CMS GitHub App устанавливается только на нужный репозиторий.
- Владелец приглашается по email и видит только свой сайт.
- Он не может править `.pages.yml`, участников и настройки публикации.

---

## 15. Проверяй ключевые сценарии вручную

Перед сдачей убедись, что работает:

- кнопка «Построить маршрут» ведёт к конкретному адресу (не на главную карт);
- «Открыть адрес на карте» открывает точку;
- телефон кликабелен;
- Telegram-ссылка формируется с закодированным текстом;
- «Скопировать заявку» копирует текст;
- MAX-кнопка копирует текст и открывает чат;
- валидация не пропускает пустые и неверные поля;
- нет горизонтальной прокрутки на мобильном.

---

## 16. Стиль кода

- TypeScript в strict-режиме, без `any` без необходимости.
- Комментарии — по-русски и по делу: объясняют «почему», а не «что».
- Отступ 2 пробела, имена по смыслу.
- Не оставляй закомментированный код и мёртвые функции.
- После работы не должно оставаться неиспользуемых импортов и переменных
  (`noUnusedLocals` включён — сборка упадёт).

---

## 17. Работа с контентом и самопроверка

Если задача касается контента:

1. Правишь `content/*.json` — проверь, что JSON валиден.
2. Добавил поле — добавь его в типы и в `.pages.yml`.
3. Убедись, что компонент корректно работает с пустым значением
   (пустой логотип, пустой отзыв, отсутствующие координаты).

Самопроверка перед завершением:

- [ ] `npm run typecheck` — без ошибок
- [ ] `npm run build` — успешно
- [ ] нет `any` и неиспользуемого кода
- [ ] данные компании не захардкожены в компонентах
- [ ] мобильная версия без горизонтальной прокрутки
- [ ] нет ложного сообщения об отправке заявки
- [ ] нет токенов и секретов
- [ ] `.pages.yml` и типы обновлены, если менялась структура данных
