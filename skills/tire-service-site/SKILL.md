# SKILL: сайт шиномонтажа

Рабочая инструкция по этому проекту. Дополняет `AGENTS.md` и `PROJECT_BRIEF.md`
и содержит конкретику: структуру, правила и чек-лист.

---

## Назначение проекта

Статический одностраничный сайт локального шиномонтажа (Щёкино, Тульская область).
Работает без сервера и базы данных, публикуется на GitHub Pages, контент
редактируется владельцем через Pages CMS. Один шаблон используется для разных
компаний: на каждую — свой репозиторий, домен и набор данных.

## Архитектура

```
content/*.json  ──(импорт на этапе сборки)──►  React-компоненты
        ▲                                            │
        │ commit                                     ▼
Pages CMS ──► GitHub repo ──► GitHub Actions ──► dist/ ──► GitHub Pages
```

- Контент — 4 JSON-файла, типизированы в `src/types/content.ts`.
- `src/data/content.ts` импортирует JSON статически (не `fetch`), поэтому
  данные гарантированно попадают в бандл.
- После сборки — только статические файлы. Серверного кода нет.

### Ключевые модули

| Файл | Отвечает за |
| --- | --- |
| `src/lib/paths.ts` | Пути к файлам с учётом `BASE_URL` (подпапка репозитория или корень домена), инициалы для текстового логотипа |
| `src/lib/maps.ts` | Ссылки «Построить маршрут» и «Открыть адрес на карте», `tel:` |
| `src/lib/booking.ts` | Текст заявки, Telegram-ссылка, MAX-ссылки, буфер обмена |
| `src/lib/validation.ts` | Проверка формы, формат телефона, автоформатирование |
| `src/components/Seo.tsx` | title, meta, Open Graph, JSON-LD LocalBusiness |
| `src/App.tsx` | Сборка страницы, «маршрут» по хэшу `#privacy` |

## Правила работы с данными

1. **Никогда не хардкодь** название, адрес, телефон, цены и тексты в компонентах.
2. Любое новое поле добавляй в трёх местах: `src/types/content.ts`,
   соответствующий `content/*.json`, `.pages.yml`.
3. Компонент обязан корректно работать с пустым значением
   (пустой логотип, пустая ссылка, `null` в координатах и цене).
4. Видимость и порядок — через `isVisible` и `sortOrder`; фильтрация
   централизована в `src/data/content.ts`, не в компонентах.
5. JSON должен оставаться валидным. Проверяй после правки.

## Правила работы с фотографиями

### Две вариации

1. `displayMode` в `site.json` переключает вариацию: `photos` или `no-photos`.
2. `no-photos` — дизайн-блоки вместо снимков: графическая панель на первом
   экране и блок «Как мы работаем» с цифрами и этапами.
3. Если `photos`, но видимых фото нет — `src/data/content.ts` сам
   переключает на `no-photos`. Пустая галерея появиться не должна.
4. `isPhotoLess` — флаг, который компоненты используют для выбора разметки.

### Файлы

1. Сначала проверь `public/images/company/` — реальные фото приоритетнее заглушек.
2. Реальные фото найдены → используй их, заглушками не заменяй.
3. Фотографий нет → используй `public/images/placeholders/` и пометь
   `isPlaceholder: true`.
4. Не подключай случайные внешние ссылки: они могут перестать работать.
5. Каждая фотография: `src`, `alt`, `caption`, `isVisible`, `sortOrder`, `isPlaceholder`.
6. Первое видимое фото по `sortOrder` становится главным на первом экране.
7. Требования: JPG/PNG/WebP/SVG, около 1600×1200, до 500 КБ.

## Правила работы с логотипом

1. Логотип необязателен.
2. Указан файл, он загрузился → показываем изображение, сохраняем пропорции,
   задаём alt-текст.
3. Логотипа нет → текстовый знак с инициалами и названием.
4. Файл не найден → `onError` скрывает картинку, остаётся текстовый знак.
5. Не допускай битой картинки и пустого места — дизайн должен выглядеть завершённым.
6. Поддержка PNG, JPG, WebP, SVG; корректный вид на мобильных.

## Правила Telegram

1. **Бот и Bot API запрещены.** Из статики сообщение в чужой личный чат
   отправить невозможно — это ограничение Telegram, а не недоработка.
2. Сайт только готовит текст и открывает чат.
3. Порядок: `telegramUsername` → `https://t.me/{username}?text={encoded}`;
   иначе `telegramPhone` → переход по номеру; иначе предложить звонок и копирование.
4. Текст обязательно кодируется `encodeURIComponent`.
5. Сообщение пользователю: «Telegram открыт с готовым текстом заявки.
   Нажмите кнопку отправки в Telegram, чтобы передать заявку владельцу».
6. **Никогда не показывай «Заявка отправлена»** до действия пользователя.

Формат текста заявки (не менять без причины):

```
Новая заявка с сайта

Имя: {name}
Телефон: {phone}
Услуга: {service}
Комментарий: {comment}
Компания: {companyName}
```

## Правила MAX

1. MAX — дополнительный канал, включается флагом `maxEnabled`.
2. Кнопка «Написать в MAX»: сформировать текст → скопировать в буфер → открыть профиль.
3. Сообщение: «Текст заявки скопирован. Вставьте его в открывшийся чат MAX
   и отправьте владельцу».
4. Если задан `maxShareUrl` — добавить закодированный текст как параметр `text=`.
5. Не утверждать, что заявка отправлена.
6. Всегда есть универсальная кнопка «Скопировать заявку».

---

## Правила Pages CMS

1. Конфигурация — `.pages.yml` в корне. Синтаксис брать из
   <https://pagescms.org/docs/configuration/>, не выдумывать.
2. Редактируются только `content/*.json` и изображения.
3. Недоступны: компоненты, CSS, HTML, GitHub Actions, `.pages.yml`,
   структура проекта, другие сайты. Это ограничение обеспечивает сам Pages CMS.
4. Владелец не получает PAT и не нуждается в GitHub-аккаунте.
5. Приглашение — по email через раздел участников Pages CMS.
6. Названия полей — по-русски, с пояснениями для владельца.
7. Не добавляй редактор произвольного HTML.

---

## Правила GitHub Pages

1. Сборка идёт в `dist`.
2. GitHub Actions: зависимости → typecheck → определение base → build →
   Pages Artifact → deploy.
3. `BASE_URL` определяет пути; все пути из контента прогоняются через `assetPath()`.
4. `public/CNAME` есть → base `/`; нет → base `/<имя-репозитория>/`.
5. Никакой серверной маршрутизации: внутренние экраны — по хэшу.
6. `public/admin/index.html` должен попадать в сборку (проверяется в workflow).

## Жёсткие запреты

| Запрещено | Причина |
| --- | --- |
| Telegram-бот и Bot API | Статика не может писать в личный чат; нужен backend |
| Supabase и любые БД | Сайт должен быть статическим |
| Обязательный backend / VPS / платный сервер | Статический хостинг на GitHub Pages |
| Токены и секреты в клиентском коде | Репозиторий публичный |
| `localStorage` как основное хранилище контента | Источник правды — файлы в репозитории |
| Фальшивая админка с имитацией сохранения | Вводит владельца в заблуждение |
| Сообщение «Заявка отправлена» до действия пользователя | Ложь: заявка ещё не ушла |
| `mailto:` как основной способ связи | Неудобно клиенту, теряются заявки |
| Придуманные отзывы от имени реальных людей | Недобросовестная практика |
| Хардкод данных компании в компонентах | Ломает перенос на другую компанию |
