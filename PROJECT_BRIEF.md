# PROJECT_BRIEF — сайт шиномонтажа (Щёкино, Тульская область)

Краткое описание задачи и границ проекта. Читается первым, до кода.

---

## 1. Задача

Сделать современный светлый одностраничный сайт для локального шиномонтажа,
который:

- понятно объясняет услуги и показывает цены;
- показывает фотографии и отзывы;
- даёт контакты, маршрут и быструю запись;
- открывает чат владельца в Telegram с готовым текстом заявки;
- дополнительно поддерживает мессенджер MAX;
- работает без собственного сервера;
- размещается на GitHub Pages;
- редактируется владельцем через бесплатную Git-based CMS;
- легко копируется под другой шиномонтаж без правки кода.

Визуальный ориентир: <https://landing48.ru/examples/tire-service/>
(только логика блоков, качество подачи и направление дизайна — без копирования).

---

## 2. Технологический стек

**Используется:**

- React, TypeScript, Vite
- Современный CSS с переменными (без UI-библиотек)
- GitHub Pages + GitHub Actions
- Pages CMS (`https://app.pagescms.org/`)
- JSON-файлы как источник контента
- Изображения внутри GitHub-репозитория

**Не используется (жёсткий запрет):**

- Supabase
- любые базы данных
- Telegram-бот и Telegram Bot API
- серверная отправка форм
- обязательный VPS
- платный backend
- GitHub Personal Access Token в клиентском коде
- токены и секреты внутри JavaScript
- `localStorage` как основное хранилище контента
- фальшивая админка, создающая видимость сохранения данных
- `mailto:` как основной способ связи

После сборки сайт — полностью статический набор файлов.

---

## 3. Аудитория и тон

- Локальный клиент из Щёкино и окрестностей.
- Понимает конкретику: цену, время, адрес, «что будет с моим колесом».
- Не любит длинные тексты и абстрактный маркетинг.

Дизайн: светлый, аккуратный, визуально дорогой, для автомобильного бизнеса.
Белый или тёплый светлый фон, графитовый текст, тёмно-синий вторичный цвет,
оранжевый акцент, крупные заголовки, выразительная кириллическая типографика,
мягкие тени, аккуратные скругления, умеренные анимации.

**Не используется:** фиолетово-белый шаблон, стандартный вид Bootstrap,
перегруженная тёмная тема, длинные стены текста, обилие градиентов,
случайные декоративные элементы, чрезмерные анимации.

## 4. Структура страницы

1. **Header** — логотип или название, телефон, кнопка «Записаться», мобильное меню.
2. **Первый экран** — заголовок, описание, город, большая фотография,
   «Записаться», «Позвонить», «Построить маршрут», короткие преимущества, рейтинг.
3. **Услуги** — название, описание, цена, единица измерения, кнопка записи,
   поддержка «от» и «по запросу».
4. **Цены** — таблица с пояснением о зависимости от размера колеса и состояния шины.
5. **Преимущества** — опыт, оборудование, скорость, гарантия, подъезд, запись.
6. **Галерея** — 4–8 фото, адаптивная сетка, модальное окно, подписи, alt.
7. **Отзывы** — имя, оценка, текст, дата, ссылка на конкретный отзыв Яндекс Карт,
   кликабельная карточка, кнопка «Все отзывы», рейтинг и количество.
8. **Запись** — форма без backend (см. раздел 6).
9. **Контакты** — адрес, телефон, режим работы, Telegram, MAX, Яндекс Карты,
   «Позвонить», «Построить маршрут», «Открыть адрес на карте», карта.
10. **Footer** — название, контакты, ссылки по странице, политика
    конфиденциальности, обработка персональных данных.
11. **Мобильная нижняя панель** — фиксированные «Записаться» и звонок.

## 5. Данные компании

Все изменяемые данные — только в `content/`:

| Файл | Содержимое |
| --- | --- |
| `content/site.json` | Компания, контакты, мессенджеры, карты, рейтинг, SEO, первый экран |
| `content/services.json` | Услуги, цены, единицы измерения, порядок, видимость |
| `content/reviews.json` | Отзывы, оценки, даты, ссылки на Яндекс Карты |
| `content/gallery.json` | Фотографии, подписи, alt, порядок, флаг заглушки |

Поля `site.json`: `companyName`, `shortDescription`, `city`, `region`,
`address`, `phone`, `workingHours`, `logo`, `telegramUsername`, `telegramPhone`,
`maxProfileUrl`, `maxShareUrl`, `maxEnabled`, `yandexMapsUrl`, `latitude`,
`longitude`, `rating`, `reviewCount`, `heroTitle`, `heroDescription`,
`advantages`, `seoTitle`, `seoDescription`, `ogImage`, `favicon`.

**Название, адрес, телефон и цены никогда не хардкодятся в React-компонентах.**

Все сущности типизированы в `src/types/content.ts`.

## 6. Форма записи без backend

Поля: имя, телефон, услуга, комментарий, чекбокс согласия, скрытый honeypot.
Дата и время не спрашиваются — их согласует владелец в переписке.

Форма **не** отправляет данные на сервер и **не** сохраняет их в базу.

### Telegram

1. Проверить поля.
2. Собрать текст:

   ```
   Новая заявка с сайта

   Имя: {name}
   Телефон: {phone}
   Услуга: {service}
   Комментарий: {comment}
   Компания: {companyName}
   ```

3. Закодировать через `encodeURIComponent`.
4. Открыть `https://t.me/{username}?text={encodedMessage}`.
5. Если username нет — использовать переход по номеру телефона.
6. Сообщение пользователю: «Telegram открыт с готовым текстом заявки.
   Нажмите кнопку отправки в Telegram, чтобы передать заявку владельцу».

**Никогда не показывать «Заявка отправлена», пока пользователь не нажал
отправку в мессенджере.**

### MAX (дополнительный канал)

1. Собрать текст заявки.
2. Скопировать его в буфер обмена.
3. Открыть `maxProfileUrl` (или `maxShareUrl` с добавленным закодированным текстом).
4. Сообщение: «Текст заявки скопирован. Вставьте его в открывшийся чат MAX
   и отправьте владельцу».

### Кнопка «Скопировать заявку»

Универсальный вариант: копирует текст в буфер, чтобы клиент отправил его
в любом мессенджере вручную.

### Валидация

Обязательные имя, телефон, услуга и согласие; проверка формата телефона
(10–15 цифр); лимит комментария; honeypot; защита от повторного нажатия;
понятные ошибки; автоформатирование телефона; поддержка кириллицы;
состояние загрузки; состояние успешного копирования.

## 7. Админ-панель

Основной инструмент — **Pages CMS**. Конфигурация: `.pages.yml` в корне.

Редактируются: общие настройки, логотип, услуги и цены, фотографии, отзывы,
контакты, Telegram, MAX, Яндекс Карты, SEO-поля.

Не редактируются через CMS: React-компоненты, CSS, HTML-структура,
GitHub Actions, `.pages.yml`, структура проекта, другие сайты.

Страница `public/admin/index.html` — **не CMS**. Это честная инструкция
для владельца: где открыть панель, какие данные можно менять, что после
сохранения сайт обновится автоматически. Кнопка ведёт на
`https://app.pagescms.org/`.

### Доступ владельца

1. Разработчик создаёт репозиторий компании.
2. Устанавливает Pages CMS GitHub App на этот репозиторий.
3. Настраивает `.pages.yml`.
4. Приглашает владельца по email.
5. Владелец принимает приглашение и входит в панель.
6. Видит только этот репозиторий и меняет только контент и изображения.
7. После сохранения сайт пересобирается автоматически.

Владелец не получает: PAT, доступ к другим репозиториям, права администратора
GitHub, доступ к коду, возможность править `.pages.yml`, возможность
приглашать других. Это ограничение обеспечивает сам Pages CMS
(collaborators не имеют доступа к конфигурации и управлению участниками).

## 8. Хостинг

- Отдельный репозиторий на каждую компанию.
- Отдельный домен на каждую компанию.
- Отдельный набор контента на каждую компанию.
- Отдельный доступ владельца на каждую компанию.

GitHub Actions при push в `main`:

1. устанавливает зависимости;
2. проверяет TypeScript;
3. определяет базовый путь (свой домен или подпапка репозитория);
4. собирает проект в `dist`;
5. загружает `dist` как Pages Artifact;
6. публикует сайт через GitHub Pages.

Серверная маршрутизация не используется. `CNAME.example` — шаблон для своего
домена; после добавления `public/CNAME` базовый путь автоматически становится `/`.

## 9. SEO

`title`, meta description, Open Graph, favicon, JSON-LD LocalBusiness,
корректная структура h1–h3, alt-тексты, город Щёкино, регион Тульская область.

Естественные ключевые фразы: шиномонтаж Щёкино, шиномонтаж в Щёкино,
балансировка колёс Щёкино, ремонт шин Щёкино, замена шин Щёкино. Без переспама.

---

## 10. Критерии готовности

- Проект устанавливается, запускается и собирается без ошибок.
- TypeScript проходит без ошибок, TODO и заглушек в коде нет.
- GitHub Pages раздаёт сайт, пользовательский домен поддерживается.
- Нет горизонтальной прокрутки на телефоне, планшете и мониторе.
- Реальные фотографии используются, если они есть; заглушки только при их отсутствии.
- Логотип можно заменить; сайт корректно работает и без логотипа.
- Услуги, цены и отзывы отображаются; ссылки на отзывы открываются.
- Кнопка строит маршрут до конкретного адреса; адрес открывается на карте.
- Телефон, Telegram и MAX кликабельны.
- Текст заявки копируется; ложного сообщения об отправке нет.
- `/admin/` не выдаёт себя за CMS и понятно объясняет работу Pages CMS.
- Во фронтенде нет секретов и токенов.
